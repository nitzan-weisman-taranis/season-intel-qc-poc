14	SEASON_ANALYSIS_EMERGENCE_PHENOLOGICAL_STATE
Analysis
Phenological state rules: (1) uniformity at the latest early-season reading is NOT a simple distinct-stage count — 1 stage is uniform; 2 adjacent stages (per the corn stage order) are uniform regardless of split; 2 non-adjacent stages or 3 stages are uniform only if the dominant stage reaches 75%; 4+ stages are never uniform; the model should copy the deterministic "(Phenological stage uniformity: ...)" label appended to the mission data rather than recompute this; (2) if not uniform, the emergence section must flag it explicitly; (3) if phenological state data is absent from the input, the emergence section must NOT mention it at all — "cannot be assessed," "no data," or any similar phrase scores 0

18	SEASON_ANALYSIS_EMERGENCE_CV_ABSENT_NO_UNIFORMITY

19	SEASON_ANALYSIS_NUTRIENT_SN_STAGE_LEAD
Analysis
When S or N deficiency was first detected before a significant rainfall event, the nutrient description must lead with the growth stage at first detection and frame rainfall as an intensifying factor — not frame the deficiency as having "appeared following heavy rainfall." Reserve "appeared following heavy rainfall" only when deficiency first appeared after the rain.
20	SEASON_ANALYSIS_NUTRIENT_SN_STAGE_LEAD_WEATHER_CONTEXT
Analysis
Same stage-lead rule as SEASON_ANALYSIS_NUTRIENT_SN_STAGE_LEAD, applied to the Weather Context section (the Nutrients-section check never sees Weather Context, and Weather Context is composed independently and can make its own S/N rain-causal claim via the "Nutrient deficiency driver" bullet): a rain-causal claim there must not frame a deficiency already present at an earlier mission as having "appeared following" the rain — use "intensified following" instead — and any cited rain-window date range must match the window immediately preceding the deficiency's actual first detection.
21	SEASON_ANALYSIS_NUTRIENT_LEACHING_SN_ONLY
Analysis
Rain/leaching causal framing for a nutrient deficiency ("appeared/intensified following heavy rainfall," "leaching") is reserved for Sulfur or Nitrogen — Potassium, Phosphorus, and Magnesium are structural deficiencies (see the STRUCTURAL DEFICIENCY TRIGGER path) and must never be described as rain/leaching-driven anywhere in the analysis — including the Weather Context section, where this most often leaks in — regardless of Status.
22	SEASON_ANALYSIS_EMERGENCE_GDD_QUALIFIER
Analysis
When GDD at VE notably exceeds the typical corn VE range of 100–120 GDD (base 50°F), the emergence description must briefly qualify the GDD value as later than typical — e.g., "at 161 GDD, later than typical for VE." Do not cite a delayed GDD value without context.
23	SEASON_ANALYSIS_INSECT_CRITICAL_WINDOW_2
Analysis
v2 of SEASON_ANALYSIS_INSECT_CRITICAL_WINDOW, run side by side for comparison before v1 is retired (added 2026-08-14 after v1 was found to be almost entirely false positives against a live SA batch). Same rule, but: aggregates ALL per-mission "Critical window:" occurrences for an insect (an insect within its window at least once may be characterized as significant even if other missions caught it outside); scopes the narrative search to the Insects category's own Description: prose, not the whole analysis text; and only flags a significant/negligible mismatch when it can be attributed to a clause naming this insect alone, skipping mentions entangled with another insect or category rather than guessing.
24	SEASON_ANALYSIS_EMERGENCE_RAINFALL_THRESHOLD
Analysis
When rainfall is cited as a cause of delayed emergence, it must meet the excess precipitation threshold (≥2 in within 48 hrs or ≥3 in within 72 hrs of planting). A single-day "heavy precip" data flag (1–2 in on one day) does NOT meet this threshold — only cite rain as an emergence stressor if the 48-hr window total is ≥2 in or the 72-hr window total is ≥3 in; if neither is met, citing the rainfall figure at all scores 0. A cumulative planting-window total (e.g., "3.1 in of rain in the planting window") does NOT qualify. Any total spanning more than 72 hours (e.g., "6.1 in over 24 days after planting") is also a cumulative total and scores 0 regardless of how the timeframe is described. Neither must be cited as an emergence stressor. If rainfall was adequate in total but arrived after 7 days from planting (Delayed rainfall), the analysis must use the Delayed rainfall matrix row framing — not cite a specific rainfall amount as a stressor.
25	SEASON_ANALYSIS_EMERGENCE_MULTIPASS_WEATHER
Analysis
The single-flight rule is universal — there is no multi-flight exception for any tier (optimal, sub-optimal, or poor). The analysis emergence section must never cite a second mission's stand-count % or GDD value alongside the final one, and must never use trajectory language ("advancing to", "advanced to", "reaching", "rising to") — report the latest reading only, regardless of tier.

Analysis

31	SEASON_ANALYSIS_NO_MERGED_STAGE
Analysis
A growth stage must be cited as the mission's single Representative (dominant) stage — never two stage buckets joined by a slash (e.g. "VT-R1/R2-R4", "V3-V4/V4-V5").
32	SEASON_ANALYSIS_YIELD_IMPACT_MATERIALITY_CONSISTENCY
Analysis
Every threat category's "Yield impact: yes/no" call must match its own "Materiality:" line (both sourced from the same CATEGORY STATUS ground truth) — a Negligible/None-materiality category (weeds, diseases, nutrients, or insects) can never carry "Yield impact: yes", even when the threat was active during a sensitive growth-stage window.
33	SEASON_ANALYSIS_SINGLE_DETECTION_NO_ESCALATION
Analysis
A category scenario-classified as "Single Detection" has exactly one data point — "escalation"/"escalating" language must never be used for it, since escalation implies a second, higher observation that a single detection by definition does not have.
34	SEASON_ANALYSIS_PRECIPITATION_EVENT_GROUNDED
Analysis
A rainfall amount attributed to a single named day must match a "heavy precip" stress flag in the weather data. season_data publishes per-window TOTALS and, only where a day crosses the threshold, a dated heavy-precip flag — it never gives a daily breakdown, so any other single-day amount describes a day the record does not. Window totals are untouched.
35	SEASON_ANALYSIS_PRECIP_WINDOW_ATTRIBUTION
Analysis
A precipitation total cited for a specific date range (e.g. "2.2 in of rain between Jun 28-Jul 15") must be that window's own total in season_data -- not another window's figure reused against the wrong dates. Distinct from SEASON_ANALYSIS_PRECIPITATION_EVENT_GROUNDED, which only grades single-day breakdowns, and from the NUTRIENT_SN_STAGE_LEAD family, which validates the date range but not the amount and only for nutrient-causal sentences.
36	SEASON_ANALYSIS_PRECIP_DOMINANT_EVENT_ATTRIBUTION
Analysis
When a weather window's total is almost entirely one heavy-precip-flagged day (that day alone clears the ~2 in heavy-precip materiality threshold, and the window's remaining precipitation does not), the analysis must cite that day as the event -- not the multi-day window range, which understates how concentrated the rainfall actually was and buries the actual point of interest.
37	SEASON_ANALYSIS_WEED_SPECIES_MISSION_GROUNDED
Analysis
A weed species named at one specific mission must be a species that mission's WEEDS block actually recorded. The weed engine grades a single entity (overall pressure) and never per-species, and NO_FABRICATED_THREATS only asks whether a species appears somewhere in the season — so a real species pinned to the wrong mission is checked by nothing.
38	SEASON_ANALYSIS_FIRST_DETECTION_MISSION_GROUNDED
Analysis
A category section's "First detected:" field must name a mission whose block actually records that category. The stage-attribution engine faults a mis-staged first detection only through a clause naming an entity it knows; this field names no entity, so a section whose threat was removed as fabricated could keep a first detection pointing at a mission with no data for the category at all.
39	SEASON_ANALYSIS_SPATIAL_CLAIMS_GROUNDED
Analysis
Spatial claims in the analysis must not contradict season_data's own spatial statements: the emergence section must not place low/high stand-count pockets or regions in a field whose EMERGENCE block reports "No distinctive low or high stand count regions detected", and a disease description must not deny spatial concentration when the record measures one. Grades contradiction only — silent where the data makes no spatial statement.
40	SEASON_ANALYSIS_FIRST_PERCENT_DETECTIONS_PHRASE
Analysis
For disease, insect, and nutrient detections, the first % metric per threat category must be followed by "detections in the field" in the analysis text — the phrase must not repeat for later % values of the same threat. Mirrors the summary-side check; previously only enforced on the summary, so the analysis could cite the same figure without the phrase.
41	SEASON_ANALYSIS_TREND_WORD_ACCURACY
Analysis
A sentence must not describe a threat with a persistence/plateau verb ("remained", "persisted", "still present", "held", "continued") when its own cited percentages show a real decrease and no decreasing-family word ("decreasing", "consistent with management", "likely managed", "reduced") is also present in that sentence.
42	SEASON_ANALYSIS_WEED_TREND_GROUNDED
Analysis
A weed sentence must not use resolution/control language ("controlled", "resolved", "no longer a factor", "effectively controlled") when the record's actual final-mission Pressure label is still moderate or higher, nor claim a decrease when the final mission's label never actually dropped below the season's peak. Grounded directly in season_data's per-mission Pressure labels (weed severity has no percentage to cite), not in whatever the sentence itself happens to state — closes a gap TREND_WORD_ACCURACY cannot see, since that check only catches a persistence verb contradicted by a percentage cited in the SAME sentence, never a resolution/decrease claim checked against season_data itself.
43	SEASON_ANALYSIS_NUTRIENT_TREND_GROUNDED
Analysis
A nutrient sentence must not claim an element is resolved/no-longer-detected when season_data's final mission still reports a real (>0%) detection for that same element. Per-element, not per-category — a category-level Unresolved status can coexist with one specific nutrient genuinely having resolved.
44	SEASON_ANALYSIS_DISEASE_TREND_GROUNDED
Analysis
A disease sentence must not claim resolution ("gone by X", "no longer detected") for a pathogen still in-field at the record's true final mission, regardless of which mission the sentence itself cites as the resolution point. Per-pathogen, reusing the same processors/disease_detections.py mission parser DISEASE_PCT_MISATTRIBUTION already trusts.
45	SEASON_ANALYSIS_STAGE_CITED_NOT_RECORDED
Analysis
A growth-stage token cited anywhere in the analysis must match some mission's actual (Representative, or clearly-dominant) stage reading in season_data -- never a stage no mission recorded. Dominant pattern (c) from the original annotator review: a fabricated stage citation, distinct from the trend-language checks above.
46	SEASON_DATA_REPRESENTATIVE_STAGE_VALID
Analysis
Every "Representative stage: X" annotation in season_data itself must be one of the crop's known growth-stage buckets (CORN_PHENOLOGICAL_STAGE_ORDER / SOY_PHENOLOGICAL_STAGE_ORDER in constants/incidents.py) -- a GT data-quality check on the source, not on any generated section. Grouped with the analysis criteria purely so it runs exactly once per record; it does not read season_analysis.
47	SEASON_DATA_INSECT_NO_THREAT_REQUIRES_NO_DETECTION
Analysis
CATEGORY STATUS must not read "Insects: Status=No Threat" when season_data records any insect detection above 0%. The requirements doc's Priority Rubric defines No Threat as "Nothing detected -- omit section entirely", so a measured detection contradicts the label. A directive-vs-source check on the pipeline's own input (like SEASON_DATA_REPRESENTATIVE_STAGE_VALID), not on generated text: field 1312426 emitted Status=No Threat over chewing damage at 5.6%/9.5% and grasshopper at 1.0%, and the model correctly copied it as "no insect feeding pressure was detected".
48	SEASON_ANALYSIS_NUTRIENT_STAGE_ATTRIBUTION
Analysis
A nutrient claim attributed to a specific stage must match that mission's own NUTRIENTS data -- not a stage whose mission reports no nutrient activity at all ("attributes activity to V4-V5; that mission reports none"), and not a different element than the one the mission actually lists ("names potassium at R2-R4; that mission lists other nutrients only").
49	SEASON_ANALYSIS_DISEASE_STAGE_ATTRIBUTION
Analysis
A disease claimed in-field at a specific stage must match that mission's own DISEASES data -- not a stage with no disease activity at all, and not a disease that was only regional (or absent) there while a different one was actually in-field ("places Holcus Leaf Spot at V5-V12; not detected in-field there").
50	SEASON_ANALYSIS_DISEASE_RESOLUTION_STAGE
Analysis
C1-ext-b: a claim that a disease was no longer detected must be dated -- by a growth-stage reference, or by the fallback the requirements doc itself permits ("at final assessment"). The reviewer-requested literal template "no longer detected by R2-R4" is deliberately NOT enforced: GROUNDING_AUDIT.md found no such template in the doc. A missing resolution statement is not flagged here -- that belongs to SEASON_*_DISEASE_PER_PATHOGEN_TRAJECTORY.
51	SEASON_ANALYSIS_CATEGORY_ABSENCE_GROUNDED
Analysis
C1-ext-c: a blanket claim that a whole threat category had no detections across any/all missions must not be contradicted by any mission block. Requires a universal scope quantifier; late-season / early-season wording narrows the mission window checked.
52	SEASON_ANALYSIS_WEED_CONTROL_STAGE
Analysis
C1-ext-a: a weed control-achieved claim ("controlled by X", "declined to mild by X") must name a stage whose mission was actually at or below the controlled (mild/none) Pressure label, and pressure must not exceed that level again afterwards. Scoped to the banned-phrasing rule in the doc; the stronger reviewer "must name the EARLIEST controlled mission" reading is deliberately NOT implemented -- it fired on 58/412 GT fields, almost all correct prose, and has no doc basis.
53	SEASON_ANALYSIS_WEED_STAGE_ATTRIBUTION
Analysis
A weed-pressure severity, peak or first-detection claim tied to a growth stage must match the Pressure label the mission at that stage actually recorded. Per the requirements doc SS Content-Weeds the engine validates OVERALL pressure, not per-species trajectories (which the doc forbids the output from containing at all).
54	SEASON_ANALYSIS_TREND_VERB_GROUNDED
Analysis
A trajectory verb must agree with the values either side of it, whether those are severity labels or percentages. "Weed pressure was moderate at V0-VE, escalated to moderate at V1-V2" asserts a rise between two equal levels; a "declined to high" after "mild" asserts a fall that is a rise; and "first detected at Mission 4 at 79.0% detections, increased to 47.4% at Mission 5" asserts a rise the two readings refute. Judged from the text alone — the value the verb moves FROM is the nearest one before it (in the same sentence for a label, the same clause for a reading, since one sentence routinely carries two entities' percentages) — so it is independent of whether the values themselves match the missions (SEASON_*_TREND_GROUNDED) and of whether the missions run forwards (SEASON_ANALYSIS_TREND_CHRONOLOGICAL).
55	SEASON_ANALYSIS_TREND_CHRONOLOGICAL
Analysis
Within one category Description sentence, the missions cited must run forward through the season — a trend may rise and fall, but it may not double back in time (e.g. "escalated to high at Mission 4 (V5-V6), then declined to mild at Missions 3 (V3-V4), 5 (VT-R1), and 6 (R2-R4)"). Graded on the citation sites the stage-attribution engine recognises, so reference windows and backward references ("no species detected after Mission 4") are not trend points.
56	SEASON_ANALYSIS_INSECT_STAGE_ATTRIBUTION_2
Analysis
v2 of SEASON_ANALYSIS_INSECT_STAGE_ATTRIBUTION, run side by side for comparison before v1 is retired (added 2026-08-15 after v1 was found to be 7/10 false positives on a live SA batch). Same rule, but: matches "detected" + stage token within the same clause only, not anywhere later in the sentence (compound sentences naming multiple insects were letting one insect's bare "detected" borrow a different, later insect's own stage citation); skips any clause with a negated "detected" ("not detected", "went undetected") rather than reading it as a positive claim; and resolves insect mentions through an alias map so a narrative eliding season_data's generic suffix ("stink bug" for "stink bug damage") still resolves correctly instead of falling back to an unrelated nearby insect name. A claim that cites an accurate 0%/absent value at one endpoint of a season-long range (e.g. "ranging from 0.0% at V1-V2 to 0.7% at R2-R4") is still flagged -- that framing is what this check exists to catch, not a matching bug.
57	SEASON_ANALYSIS_NUTRIENT_RAIN_MAGNITUDE_THRESHOLD
Analysis
A nitrogen/sulfur deficiency must not be attributed to a rain event below the ~2 in heavy-precip materiality threshold used elsewhere in this record's weather data -- too small to plausibly drive leaching.
58	SEASON_ANALYSIS_INSECT_PEAK_CITED
Analysis
A high-impact insect the analysis DESCRIBES must cite the peak reading season_data holds for it. analysis.py asks for a trajectory "across all late-season flights", a "full trajectory section" for high-impact species, and an explicit statement of "whether peak detections fell within the critical window" — a narrative built on one non-peak reading cannot do the last of those and under-reports the season. Field 1015071 records stink bug at 7.5% (M2) and 1.7% (M3) and describes only the 1.7%, contradicting its own "First detected: Mission 2" field and carrying the loss into the summary. Low-impact species are exempt (they get a Low-impact detections line, graded by SEASON_ANALYSIS_INSECT_LOW_IMPACT_FORMAT), as is chewing damage, which the Insect Stage-Impact Reference treats as supporting evidence only. An insect the section never names is SEASON_ANALYSIS_INSECT_ENTITY_COVERAGE's business, not this one's. Deliberately NOT critical, against DECISIONS.md #1: 33 of 161 records across inference_parity and the debug fifteen omit a peak this way, and hiding one result in five over an under-reported percentage is a worse trade than shipping it — the failure is incompleteness, not a false claim.
59	SEASON_ANALYSIS_INSECT_ENTITY_COVERAGE
Analysis
Every insect with a real detection in season_data must be described somewhere in the analysis Insects section. Naming it in the bare "Type:" list is NOT coverage — that field is an enumeration, and a species listed there and described nowhere is exactly the omission this grades. A supporting-only damage type (Chewing Damage, Grasshopper) is covered by the grouped low-impact clause; it does not need a trajectory, which the prompts forbid for low-impact detections. The insect counterpart of SEASON_ANALYSIS_NUTRIENT_ENTITY_COVERAGE. Not critical.
60	SEASON_ANALYSIS_NUTRIENT_ENTITY_COVERAGE
Analysis
Every individually named nutrient with a real (>0%) detection in season_data must appear somewhere in the analysis Nutrients section — not just the dominant nutrient driving the category-level scenario. Catches single-mission K/P/Mg detections silently dropped when a different nutrient (typically S or N) dominates the section narrative.
61	SEASON_ANALYSIS_INSECT_SUPPORTING_ONLY_NOT_SOLE_DRIVER
Analysis
A supporting-evidence-only insect entry (Chewing Damage — "insufficient alone to assign a yield impact characterization" per the Insect Stage-Impact Reference) must not be the sole named entry in the Insects Type field while Materiality is Moderate/Significant or Season Priority is High/Moderate.
62	SEASON_ANALYSIS_NO_BRAND_NAMES
Analysis
Analysis must not mention specific company names or product brands unless the exact name appears in season_data.
63	SEASON_ANALYSIS_ROUNDING
Analysis
All numeric values in the analysis must be rounded to one decimal place (e.g., "4.6%" not "4.56%").
64	SEASON_ANALYSIS_WEED_EFFECTIVE_PROHIBITED_EARLY_PRESSURE
Analysis
When early-season weed pressure (M1 or M2) was moderate or higher, the analysis must not credit weed management as "effective" without scoping that credit to post-emergence / later-season control — early pressure indicates pre-emergence underperformance. Describing later-season or post-emergence control as effective is explicitly permitted, as is stating that control was not effective or was achieved only after early-season competition.
65	SEASON_ANALYSIS_EMERGENCE_OPTIMAL_NO_WEATHER
Analysis
When final stand count is optimal, the analysis emergence section must report the final count only — no earlier mission counts, and no weather of any kind (including "despite" framing).
66	SEASON_ANALYSIS_NO_WEED_DROUGHT_MISATTRIBUTION
Analysis
Analysis must never attribute a weed-pressure increase to drought — drought suppresses weed growth just as it suppresses crop growth; rain events in the herbicide window are the actual driver of a weed-pressure increase.
67	SEASON_SUMMARY_TWO_PART_FORMAT
Summary
Summary must begin with **Season Conclusion:** (bold header) followed by **Season Detail:** (bold header) — both section labels must be present. Season Conclusion must be ≤40 words and contain no numeric values (no %, no specific measurements, no bu/ac). Crop growth stages (V#, R#, VT, VE, VC, and ranges like VT–R1) are not numeric values and are allowed.
68	SEASON_SUMMARY_LABELS_OWN_LINE
Summary
The **Season Conclusion:** and **Season Detail:** labels must each be followed by a single line break so their content begins on the next line — not inline on the same line as the label.
69	SEASON_SUMMARY_DETAIL_BLOCK_SEPARATION
Summary
Season Detail must be structured as blank-line-separated blocks — an emergence block and one block per detected threat category (weeds, disease, nutrients, insects), plus a closing weather block if present — not a single run-on paragraph. When 2+ categories are covered, a blank line must separate them.
70	SEASON_SUMMARY_NO_MERGED_STAGE
Summary
A growth stage must be cited as the mission's single Representative (dominant) stage — never two stage buckets joined by a slash (e.g. "VT-R1/R2-R4", "V3-V4/V4-V5").
71	SEASON_SUMMARY_FORMAT
Summary
Summary uses the required two-part structure: **Season Conclusion:** and **Season Detail:** bold headers are required and allowed; no other markdown headers, bold section labels, or bullet points are permitted
72	SEASON_SUMMARY_NO_NEXT_SEASON
Summary
Summary does not reference "next season", "upcoming season", or "next year"
73	SEASON_SUMMARY_THREAT_CATEGORIES
Summary
Each detected threat category name (or alias) appears somewhere in the summary text
74	SEASON_SUMMARY_YIELD_LANGUAGE
Summary
The Season Conclusion section must contain a single yield-impact sentence — it opens the summary, not closes it. If any threats caused yield impact, the sentence names specific threats (when few) or uses aggregate category language (when many), with hedged language ("likely reduced yield potential," "may have reduced yield potential," etc.) — never as a certainty, never with bu/ac figures or numeric values. If no threats caused yield impact, it states "No significant yield impact identified this season" or an equivalent neutral phrase. Only yield-impacting threats are named; resolved threats must not be referenced.
